# M5 WinUI screenshots and design comparison

Captures of the Milestone 5 WinUI views (import dialog and report, export dialog, the sidebar `+` menu with *Import...* and the
collection context menu with *Export...*), dark and light, taken from the Native AOT build at 1440 x 900 and compared with the
design sources in `design/mockups/`. There is **no mockup for any milestone 5 screen**, so each screen is compared with the
closest component sheet (named per screen below). The capture machine runs at 150 % display scale. Every value on screen is
fake: the Postman collection and the HAR are generated by the script, pasted through the clipboard (nothing is written to disk)
and the exported file goes to a temporary folder that is deleted afterwards.

## Regenerate

```powershell
dotnet publish src/Yaapic.App.WinUI -c Release -r win-x64 -p:PublishAot=true
pwsh tools/screenshots/Capture-M5.ps1                      # all 16 files; -Only <screen> for one screen
```

`Capture-M5.ps1` runs `Capture-WinUI.ps1` once per file, in English. The only change to the shared script is the `savepath:<file>`
step, which types a path into the system *Save* dialog (it runs in a `PickerHost` process, found through UI Automation) so that
the export can finish without a person. The script puts the sample document on the clipboard before each import capture and
restores the previous text afterwards.

## Defects found by the capture

Fixed in this card (small):

- **Import and export dialogs were taller than a 900 px window** (560 and 520 dip at 150 % scale): the *Import* / *Export...* and
  *Close* buttons were below the window edge and unreachable. Heights are now 500 (import) and 480 (export); the report list has
  a 100 dip minimum instead of 160.
- **Import dialog content clipped on the right** (*Preview* and *Copy report* cut off): the 720 dip body is wider than the
  dialog's content area (`ContentDialogMaxWidth` 760 minus the dialog padding). The bodies are now 700 (import) and 620 (export)
  dip wide.
- **Report filter toggles used the blue system accent** when checked, not the Yaapic accent. `ImportReportView` now maps the
  checked `ToggleButton` resources to the `YaapicAccentFill*` brushes.
