# M6 WinUI screenshots and visual review

Captures of the Milestone 6 WinUI views (Runner, Load test, Mock servers and Monitors windows, the folder context menu and the
status bar items), dark and light, taken from the Native AOT build (`dotnet publish -c Release -r win-x64 -p:PublishAot=true`).
There is **no mockup for any milestone 6 screen**, so each screen is only related to the closest component sheet (listed below).
The capture machine runs at 150 % display scale. The main window is 1440 x 900 px. Tool windows are no longer 1100 x 720 *physical*
pixels (see "Defects found"): they open at 1100 x 720 dip scaled by the display scale (here 1650 x 1080 px). Every value on screen is
fake: a loopback stub (`127.0.0.1:5199`) and a Yaapic mock server (`127.0.0.1:3000`) provide the responses, the data file is a
three-row CSV generated by the script, and everything lives in a throw-away workspace that is deleted afterwards.

## Regenerate

```powershell
dotnet publish src/Yaapic.App.WinUI -c Release -r win-x64 -p:PublishAot=true
pwsh tools/screenshots/Capture-M6.ps1                      # all 16 files; -Only <screen> for one screen
```

`Capture-M6.ps1` runs `Capture-WinUI.ps1` once per file in English on the `-Seed m6` fixture (a `Demo API` folder with a passing,
a failing and a script-skipped request, a `Health checks` folder, `users.csv`) and retries a capture up to three times (the folder
context menu sometimes does not open when another window takes the foreground). New capture steps: `front:<title>`,
`clickitem:<name>:<n>`, `setvalue:<edit>=<text>`, `pickcombo:<combo>=<item>`, `openpath:<file>`, `http:<url>`, `probe:<url>`,
`dump:`/`tops:` (debug), `{TEMP}` in a step, `-Window <title>` (capture a tool window) and `-Seed m6`.

## Defects found by the capture

Fixed in this card:

- **Mock servers: "Create a mock server..." (and adding a route) closed the application** under Native AOT. The route *Method* combo box took
  an `IReadOnlyList<string>` as `ItemsSource`, the stowed XAML exception documented in `ListMap.Entries`. Fixed with `ListMap.Lines` and the
  selection applied in the code-behind (commit `7c45c8a`).
- **Monitors: the Folder and Environment combo boxes were empty** and *Save* stayed disabled: the bindings rebuild the choice lists, which
  cleared the selection and wrote `null` back to the view model. The selection is now applied and read in the code-behind. The *enabled*
  switch also used the system blue instead of the Yaapic accent (`efcc2d4`).
- **Tool windows were sized in physical pixels** (1100 x 720), so at 150 % scale the Mock servers editor column was 173 dip wide and clipped
  (port, *Save*, headers cut off). Sizes are now device-independent and kept inside the work area (`26ca548`).
- **Runner layout**: the request list collapsed to a sliver as soon as a data file was loaded; *Export JUnit XML* was off the right edge; result
  rows squeezed the request name to one character; the rows list got only half of the height even when nothing was selected (`26ca548`, `2a6eba1`).
- **Load test showed "Scripts were not run during this load test."** after any test of requests that have scripts, although ADR 0019
  decides that scripts run (the capture's `skipRequest()` visibly skipped a request). The note and its test expectation were removed (`2a6eba1`).

## Deviations left open

| # | Screen | Deviation | Class |
|---|---|---|---|
| D1 | load-test-running, load-test-done | The charts end with a drop to zero at the right edge: the last bucket (the second after the end, or the second still running) is plotted with a partial count. | follow-up: leave the unfinished bucket out of the series in `LoadTestViewModel.Series` |
| D2 | load-test-* (dark) | The summary tiles use `YaapicSurfaceSunkenBrush`, which is almost the window colour in dark, so the tiles are hard to see; they read as cards in light. | follow-up: a raised surface brush for tiles in dark |
| D3 | monitors-* | The monitor list subtitle is cut (*Every 1 h - 2026-11-27 1...*); the name, folder and schedule share a 340 dip column. | follow-up: wrap or drop the last-run time |
| D4 | runner-*, load-test-* | The request list rows (`RunnerItemViewModel`) expose the type name as their UI Automation name (screen readers read *Yaapic.ViewModels.Runner.RunnerItemViewModel*), as do the result and log rows. | follow-up: `AutomationProperties.Name` on the item templates |
| D5 | runner-results-* | Skipped and passed rows have no icon, only a coloured word; the iteration number column is blank when there is one iteration. | none |
| D6 | mock-servers-* | A route generated from a request without saved example always answers `200` (`Find missing user` returns 200 although the request tests for a 404). | none (by design of the generator) |
