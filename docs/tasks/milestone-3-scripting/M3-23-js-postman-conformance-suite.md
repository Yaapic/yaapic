# M3-23: JavaScript Postman conformance suite

Status: done
Platform: any
Depends on: M3-22

## Goal

A table-driven test suite that runs typical Postman scripts end to end through `ScriptedRequestSender` and the real
QuickJS engine, so regressions in `pm` compatibility are caught, and a documented list of the known differences.

## Design decisions

- `tests/Yaapic.Scripting.Tests/Conformance/JavaScriptConformanceTests.cs` with a `TheoryData` of cases
  `(name, preRequestScript?, postResponseScript?, request, stubResponse, expectations)`; expectations are variable values,
  header values on the request that reached the fake transport, test results (name, passed, message) and console lines.
- At least 40 cases built from the idioms that dominate real collections (write each as the Postman documentation does):
  status code and status text tests; response time test; JSON value and nested value tests (`pm.response.json().data[0].id`);
  header presence/value; content type; saving a token from a JSON body to an environment variable and using it in the next
  request header through `{{token}}`; generating a timestamp, a random int and `{{$guid}}` via `pm.variables.replaceIn`;
  adding a signature header in pre-request from `pm.request.url` and body (a hand-rolled checksum, no `CryptoJS`);
  `pm.collectionVariables` counters across two sends; `pm.globals` set and unset; `pm.expect` chains (`to.have.property`,
  `to.include`, `to.be.an('array')`, `to.have.lengthOf`, `to.match`, `to.be.oneOf`, `to.eql`); `pm.response.to.have.status` /
  `have.jsonBody` / `be.ok`; array loops with `forEach`/`map`/`reduce`; `try/catch` around `json()`; `async` test with
  `await pm.sendRequest(...)`; callback-style `pm.sendRequest`; `console.log` of objects; template literals, destructuring,
  classes, optional chaining, `Array.prototype.flat`, `Object.entries`, `Intl`-free `toFixed` (QuickJS language support);
  a failing test with the exact message; an error in a post-response block keeps the response; an infinite loop times out.
- A second table asserts the **unsupported** members fail with `"... is not supported in Yaapic"`: `pm.execution`,
  `pm.iterationData`, `pm.vault`, `pm.visualizer`, `pm.require`, `pm.request.auth`, `pm.response.to.have.jsonSchema`,
  `pm.cookies.jar()`, `require('crypto-js')`, `CryptoJS`, `postman.setNextRequest`.
- `docs/scripting-compatibility.md` (new, English): the supported `pm` surface as a table (member, status
  `supported | partial | unsupported`, note) generated by hand from the two tables above, the semantic differences from
  Postman (layered write fallback, `pm.environment.name`, no `CryptoJS`/`lodash`/`moment`/`cheerio`/`tv4`/`uuid`/`atob` libs,
  `max-age` ignored in cookies, scripts see templates), and how to report a gap. Link it from `docs/adr/0009-scripting.md`.

## Out of scope
