# M1-29: Avalonia request editor view

Status: done
Platform: unix
Depends on: M1-28

## Goal

Same request editor as M1-25, in `Yaapic.App.Avalonia`.

## Design decisions

- Behaviour, texts and layout are those of M1-25; read it first.
- `Views/RequestEditorView.axaml` and reusable `Views/KeyValueEditorView.axaml` (`UserControl`s, compiled bindings,
  `x:DataType` = `RequestEditorViewModel` / `KeyValueEditorViewModel`).
- Control mapping: `SelectorBar` -> `TabControl` (Params, Headers, Body); `RadioButtons` -> two `RadioButton`s in a
  `StackPanel` with the same `GroupName`; rows -> `ItemsControl` with a `DataTemplate` of `CheckBox`, two `TextBox`es
  and a delete `Button`. Body `TextBox` with `AcceptsReturn`, `TextWrapping="NoWrap"`, monospace font resource
  `YaapicMonoFont`.
- Send/Cancel swap by `IsVisible` bound to `IsSending`. Ctrl+Enter (Cmd+Enter on macOS) sends.

Same as M1-25.

## Implementation notes

- `YaapicMonoFont` generated by the token tool points at `avares://Yaapic/...`, which does not exist in this app (the
  AOT exe crashed on the first monospace `TextBox`). `App.axaml` overrides the key with
  `avares://Yaapic.App.Avalonia/Assets/Fonts`, and the csproj links `JetBrainsMono.ttf` from the WinUI assets.
- Method, content-type and body-kind controls are driven by converters (`EditorMap`) plus code-behind handlers: no enum
  `ItemsSource` binding, as with the WinUI view.
- Verified on the Windows Native AOT exe through UI automation: editor renders, Ctrl+Enter swaps Send for Cancel and
  back once the request ends, typing a key adds a placeholder row and shows the delete button. Not verified: macOS/Linux
  (Cmd+Enter, publish), Save/dirty marker and the dirty-tab close prompt.
